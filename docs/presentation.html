05 · AI agent design

Claude proposes. Code decides. She approves.

The tool-use loop (agent.py)

  • save_business_profile — structured profile, schema-validated
  • suggest_domains · check_domain — live GoDaddy data
  • propose_website — only shows an approval card
  • create_growth_plan — 30/60/90-day plan card
  • Max 8 tool rounds · 100 s budget per turn · tool errors returned to Claude with is_error

Guardrails

  • No spending tool exists. Domains are bought on GoDaddy checkout by her.
  • Human checkpoint: nothing is built until she taps "Haan, banao".
  • Untrusted input: the browser's profile is reduced to typed, size-limited fields, wrapped as <profile> data.
  • Claude never writes HTML: forced tool calls return JSON → Jinja2 with auto-escaping.
  • AI edits validated: positive prices, real palettes, only her own photos.
  • Honest failure: if Claude fails after tools ran, finished work is kept.

08 · Security and privacy

Private by default.

Login

  • Email code, HMAC-hashed
  • 5 tries/code, 10 codes/email/day
  • HttpOnly · SameSite · Secure cookies
  • Server-side logout

Access

  • Owner check on every owner API
  • 404 for others — no IDOR, no leak
  • Ownership is insert-only
  • Rate limits on login, chat, build, orders

Data

  • Customer data outside the web root
  • Web server mounts public files only
  • Emails only to her verified address
  • Secrets only in .env

Production guard

  • ENV=production is explicit
  • Refuses to start with a default secret, no domain or no SMTP

Web

  • Auto-escaped templates
  • Parameterised SQL
  • HSTS · nosniff · frame-ancestors
  • Photos re-encoded

Containers

  • Non-root API
  • Health checks · restart policy
  • Log rotation
